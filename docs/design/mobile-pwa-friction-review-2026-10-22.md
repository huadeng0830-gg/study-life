# 手机 PWA：记录与修改减负审查

> 第一轮后续实施见[操作减负交付记录](mobile-pwa-friction-delivery-2026-10-22.md)。下文保留审查当时的现状与后续目标。

日期：2026-10-22。依据：当前工作区源码、本地移动尺寸浏览器操作、使用者反馈。

本次反馈明确为：主要使用手机浏览器／PWA；记账麻烦，其他模块也要检查；最主要的不满是记录和修改步骤太多。本报告据此调整优先级，不沿用旧方案中“主要只看课表”的使用假设。

这是体验审查与实施方案，没有修改业务代码、部署服务或使用真实账号。工作区原有大量未提交改动，均保留。本报告补充 10 月 21 日方案，不将其中的旧现状当成当前事实。

## 判断

优先降低每次操作的阅读、选择和返回成本。现有能力已经很丰富，简单场景仍经常进入完整工作流；部分省事能力虽已存在，但离高频操作较远。

“步骤太多”不全是必点按钮过多，也包括每次都要扫描无关选项、辨认两个相近入口、为了改一个字段打开完整表单。不能把屏幕上的八个类型选项误算成必须点击八次。

建议采用一致的规则：**先做最小的一步，复杂信息按需补；普通修改在原位置完成，修改后仍回到原位置。**

## 本轮证据与边界

- 启动当前源码的 Vite 开发预览；隔离 Chrome 手机模拟视口 360 × 732，设备像素比 3。
- 实际浏览今天、待办、课表、日程、清单、重要日期、账本、周回顾、校园、项目协作、一起约。
- 实际走通“午饭18元”识别并保存到账本、“只填标题创建待办”；打开待办开始面板、账本新增与详情、日程新增、清单新增、普通重要日期新增。
- 测试数据仅为隔离浏览器中的虚构记录。未写入用户正在使用的 PWA 数据。
- 课程详情、清单条目修改、通知处理、专注结束、导入及已登录协作的详细规则结合源码审查；不宣称这些完整链路已实际走通。
- 浏览器模拟不包含真实手机软键盘、系统回收、iOS 权限及通知行为；本轮没有部署线上 PWA 或测量生产速度。
- 本轮浏览器 console 检查返回 Errors 0、Warnings 0；这只覆盖本轮经过的页面，不代表全项目无错。没有运行业务全量测试或构建，因为本轮没有改业务代码。

## 已有改进应保留

手机默认已经是“今天／课表／＋记录／待办／更多”，首页已有精简模式。普通重要日期已经折叠低频字段。清单已有行内快速添加、批量添加和模板。账本已有金额快速录入、常记、连续记、分类纠正记忆，以及微信／支付宝账单文件导入。快速记录已有批量保存与撤销，且一条明确记录只需要一次显式保存。

因此，本轮不把“增加一句话记账、增加连续记、增加清单快录、增加账单导入”作为新功能重复开发。

## 记账应该怎样省事

先把“随手补几笔”和“集中整理账单”作为两个入口，不要求所有消费都现场手记。

### 随手记

```text
从账本：点记一笔 → 输入金额，按需补名称 → 记下
从全局：点＋记录 → 输入“午饭18” → 看清一行摘要 → 保存

摘要示例：支出 ¥18.00  午饭  餐饮  今天
                  点名称／分类／日期即可改
```

专用金额表单已经接近这条路径，不需要重写成更大的记账工作台。重点是让全局录入具有同等轻便的确认体验。类别不确定时明确显示“待分类”或建议，不要用连续确认打断每一笔；实际持久化策略须兼容原有分类规则。

已有“常记”应靠近输入入口，点击后预填最近金额、名称和已确认分类，用户检查后保存；沿用现有实现。连续记保留已明确选择的账户和币种需给可见摘要；日期默认今天，分摊、退款、账单关联不能无提示继承。

### 集中整理

复用现有微信／支付宝文件导入。手机预览先给笔数、收支、重复、异常和待分类摘要，再查看逐笔明细；不要求逐条打开确认。金额、方向、疑似退款、重复等异常保留复核。

这是一条文件导入路径，本次没有验证真实支付文件，也没有实现支付后自动读取或后台抓取。新增自动化接入的收益，应在手记和现有导入试用后评估。

### 修改

```text
现在：流水 → 详情 → 判断编辑／完整编辑 → 修改 → 保存
建议：流水 → 编辑 → 改所需字段 → 保存，回到原流水位置
```

金额、名称、分类、日期采用同一编辑逻辑；详情页点击某一字段也能进入这套逻辑。固定账单生成项与退款仍保留受控修改规则，不能因为统一入口而丢失关联。

## 第一轮可交付范围

集中改四处，分别验证，不把全模块一次重构：

1. **快速记录确认区**：移除手机无关说明；明确事项用紧凑摘要；类型纠正改为按需展开；保存始终可见，错误和多条内容仍可复核。
2. **账本修改**：统一编辑语义与字段覆盖，保持金额／分类／退款／分摊规则；常记与连续记沿用已有能力。
3. **待办执行**：拆开开始执行、专注、记进度；直接开始复用现有任务命令，不建立平行状态。
4. **待办轻编辑**：新增先填内容；日期支持就地修改；多阶段任务显示修改范围与冲突结果，提供撤销。

第二轮做日程表单、课程内记作业、清单就地修改和草稿恢复。第三轮再用真实已登录内容审查校园、协作与回顾。

## 验收依据

下列是目标，不是本次已经实现或测得的改善：

- 常见单条记录输入后，首屏能同时看清内容、识别结果与保存按钮；只需一次显式保存。
- 改一个常用字段不必判断“编辑／完整编辑”，也不必浏览无关字段；保存回原列表、筛选和滚动位置。
- 待办点开始直接执行，点专注明确计时，点记进度才填写检查点。项目任务继续遵循项目权限。
- 连续输入不反复收起键盘；切后台／返回／取消时的草稿行为一致，身份切换不能串数据。
- 已有多币种、退款、分摊、固定账单、重复待办、阶段联动、冲突、撤销和关联不能因简化丢失。
- 在真实 Android 浏览器与 iPhone Safari／主屏 PWA 检查键盘、输入法、底部按钮、系统返回与焦点。不能用桌面模拟通过替代这些检查。
- 以相同内容比较改版前后的点击、字段输入、滚动和找回成本，再让使用者连续用一段时间反馈。首轮成功标准是记一条、改一下更省事。

本轮改动仅为这份审查报告及忽略目录中的隔离浏览器检查产物；未进行提交、发布或版本变更。
