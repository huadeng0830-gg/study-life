# Supabase 账号与自动同步

学习生活台支持邮箱注册、密码登录、验证邮件重发、密码找回与修改、恢复登录状态，以及退出当前设备或所有设备。桌面侧栏和手机“更多”菜单都有“我的账号”入口。

账号是可选功能。未登录时可继续使用本机数据；登录后，同一账号的课程、待办、日程、账本、笔记、专注记录及同步设置自动合并到其他设备。首次登录会保留并合并当前设备的访客记录，内容冲突时先逐项确认。

## 使用行为

- “账号概览”展示邮箱、验证状态、注册时间、最近登录和账号同步；“账号安全”提供修改密码、备份入口和退出操作。
- 忘记密码时只填写注册邮箱。发送成功的提示不透露该邮箱是否注册；验证与重设邮件共享 60 秒冷却，关闭并重开面板后继续计时。
- 网页密码找回使用 PKCE，需在请求邮件的同一浏览器打开链接。桌面版通过默认浏览器进入网页设置新密码，再回到桌面版登录。恢复链接成功验证后打开新密码表单；在同一标签页刷新时保留恢复流程，退出或切换账号后清除恢复标记。
- 常规修改密码填写当前密码与两次新密码，并通过不持久化的独立认证客户端验证当前密码，随后退出临时验证会话，不替换原有会话。已验证的密码恢复会话无需旧密码。SDK 使用安装版本支持的 `current_password` 字段。新密码至少 8 位，失败保留输入供修改，成功或关闭表单后清空密码。
- 修改先保存在本机，约 4 秒后自动同步。前台每分钟检查一次其他设备的更新，回到页面或恢复联网时也会检查；关闭页面期间不会执行浏览器同步。
- 离线可继续使用，联网后自动提交。两边新增不同记录会合并；同一记录的冲突在“账号同步”中选择版本后继续。
- 退出操作先显示确认，提示当前同步是否完成，并允许先打开数据管理导出备份。确认退出后停止同步并清除当前设备的业务记录与本机副本，不删除已同步的云端记录。退出所有设备同时撤销其他设备的刷新会话；其他设备的本机数据不由此操作清除。切换账号仍沿用原有隔离流程，避免把上一账号的数据上传给下一账号。
- 未完成的本机提交通过恢复标记和 IndexedDB 副本回滚；恢复失败或本机安全模式下暂停同步。
- 数据管理只保留本地 JSON 备份导出、从备份恢复和账号同步。旧设备码、绑定码、同步空间及二维码迁移已停用；客户端会清除本机保存的旧同步凭据，远端旧空间数据不会自动删除。
- 账号会话、本机账号副本和同步基线使用独立存储，不进入以 sl_ 为边界的业务备份或同步负载。壁纸图片、运行中的计时器与设备凭据不作为账号数据上传。

## 本地与生产配置

复制 .env.example 为 .env.local，填写：

- VITE_SUPABASE_URL：独立 study-life 项目的 API URL。
- VITE_SUPABASE_PUBLISHABLE_KEY：该项目的 publishable key。

重启 Vite。前端只接受 publishable key 或兼容的 anon key，拒绝 secret 与 service_role key。真实环境文件已被 Git 忽略，示例文件只保留占位符。

Cloudflare Pages 的生产及预览构建环境也需要上述两个变量，再重新构建部署。Vite 在构建时读取变量；修改环境变量不会更新已有静态资源。账号同步直接连接 Supabase，不依赖旧 Cloudflare 同步协调器。

GitHub Actions 的网页构建、Windows 桌面打包和桌面 Release 使用仓库级 Actions Variables：`VITE_SUPABASE_URL` 与 `VITE_SUPABASE_PUBLISHABLE_KEY`。这两个值是面向客户端的公开配置，不得改用 Supabase secret 或 `service_role` key。发布工作流会验证配置并扫描最终网页/桌面 JavaScript 包；配置缺失或没有打入安装包时会阻止发布。可在仓库 **Settings → Secrets and variables → Actions → Variables** 中维护这两个变量。不要把真实值写进源码、README 或 `.env.example`。

## Supabase Auth 状态

按当前要求，邮箱验证与邮件服务暂不配置。现有项目仍使用 Supabase 默认设置：邮箱验证开启，自定义 SMTP 尚未配置。默认邮件服务限制收件范围，普通用户邮箱的注册验证仍需要完成邮件配置后验收。

后续开放注册时，可配置 Site URL、实际开发及生产 Redirect URLs，以及自定义 SMTP。代码同时支持服务端要求邮件验证或直接返回登录会话两种注册响应。

网页使用 PKCE，桌面版使用 implicit flow；兼容已有邮件中的隐式令牌。邮件回调在 Hash Router 创建前通过 SDK 交换会话，再移除地址中的令牌、一次性 code 与错误详情。密码恢复根据已验证的回调与 SDK 的 `PASSWORD_RECOVERY` 事件进入新密码表单；过期或失效链接提供可读提示。

密码重设同样依赖服务端邮件发送配置。此轮只完善客户端认证与交互，没有修改 SMTP、邮箱验证开关或生产 Auth 设置；真实邮件送达仍需完成邮件服务配置后验收。桌面版重设邮件的重定向白名单需要包含 `https://study-life.pages.dev/`。

## 数据库与访问控制

数据库迁移位于 supabase/migrations/，已应用到独立 study-life 项目：

- account_sync_snapshots：每个账号一条快照，包含业务 JSON、版本号、更新时间和设备显示名。
- RLS 与表权限限制用户只能读取和更新 auth.uid() 对应的快照，匿名访问禁止。
- write_account_sync_snapshot 是 security invoker RPC；账号归属由服务端会话确定，首次写入与后续写入都通过预期版本检查，过期提交返回冲突供客户端重新合并。
- 数据库约束检查格式、必需字段与 16 MiB 大小上限。

账号快照通过 HTTPS 传输，以 JSON 保存在 Supabase 数据库，使用登录权限和 RLS 隔离；账号同步未实现端到端加密。

## 验证

针对性测试覆盖注册表单、密码找回、PKCE 与隐式密码恢复、当前密码与新密码校验、邮件冷却恢复、退出二次确认、会话恢复、同步合并、冲突确认、过期版本拒绝、离线重试、账号隔离、迟到响应、安全模式及中断恢复。同步与账号切换测试使用虚构账号和记录，不需要真实用户数据。

supabase/tests/account_sync.sql 在事务内验证数据库 RLS、匿名拒绝、归属变更拒绝、版本并发保护与必需字段约束，最后回滚虚构测试账号和快照。

真实账号的生产验收仍需要可收信的测试邮箱：注册 → 验证 → 登录 → 两台设备修改 → 自动合并 → 离线修改 → 重连 → 退出与切换账号。测试账户与真实环境文件不得提交到仓库。

官方文档：[邮箱密码认证](https://supabase.com/docs/guides/auth/passwords)、[自定义 SMTP](https://supabase.com/docs/guides/auth/auth-smtp)、[RLS](https://supabase.com/docs/guides/database/postgres/row-level-security)。
