# 仓库重构路线

更新时间：2026-10-08

这次重构按业务边界逐块推进，保留用户已有数据与使用路径。它不是一次性改写：每一块先确认现有职责与行为，再抽出有明确输入/输出的模块，用现有路由测试和模块测试验证后继续下一块。

## 不变约束

- 不新增 npm 依赖，也不接入新的外部服务。
- 保留既有 `sl_*` 存储键及其数据语义。
- 保留 hash 路由和现有产品流程。
- 每个阶段都通过 `npm run check`；涉及样式与数据边界时补跑对应审计。
- 不自动暂存、提交或推送用户工作区改动。

1. **设置与数据管理（进行中）**：已把备份快照、校验和、版本归一化及恢复范围标签集中到 `src/composables/backupArchive.js`；`dataManagerBackup.js` 保留下载、壁纸进度与恢复回滚流程。首页模块的顺序归一化、移动、重置与默认状态查询已集中到 `src/composables/homeModules.js`；外观设置保留拖拽和键盘事件接线。农历纪念日编辑模型移入 `src/composables/lunarAnniversaryEditor.js`，统一稳定行 ID、存储归一化、氛围镜像发布与日期状态投影；`FestiveSettings.vue` 保留表单事件和展示。专注设置草稿和保存校验移入 `src/composables/focusSettingsEditor.js`，组件保留通知权限请求与表单交互。接下来继续检查其他设置分区是否存在同样稳定的业务边界。

5. **每阶段验收**：`npm run lint`、`npm run typecheck`、全量 `npm test`、`npm run build`；涉及时间、账本、备份或同步时运行其专项回归。
