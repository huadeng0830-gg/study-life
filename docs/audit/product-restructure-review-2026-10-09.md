## 2. 冗余与需要收拢的入口

- `/notes` 是旧书签兼容地址，会回到首页，不是独立笔记模块；继续保留兼容，不在导航占位。
- 过去 PC 导航把捕获、回顾、记录和页面操作拆成多组，和页面内按钮、快捷记录存在交叉。现改为「今日、学习、日程、齐行、其他」；「其他」折叠收纳低频工具。
- 手机端页面过多会挤占底栏。本轮固定四个核心槽位（今日、学习、日程、齐行），快速记录与「更多」固定可达；低频功能仍可从「更多」进入。
- 快速记录是捕获入口，任务页是确认后的任务管理入口；它们共用既有适配器和任务存储，不再创建平行捕获/任务模块。
- 课程表、考试/重要日期和日程名称相近但数据含义不同；保留页面，统一课程 ID 关联和导航归属，不合并掉用户现有记录。

## 3. 本轮页面与流程调整

- **PC 导航、手机底栏与导航设置**：导航元数据仍以真实路由为准；PC 收拢为四个核心空间加折叠「其他」，手机用四个核心入口；旧默认布局按精确匹配迁移，用户自定义排序/分组不重置。`/notes` 继续兼容。
- **待办页**：任务行按状态提供开始、续接或工作台入口；个人任务工作台显示上次进度、卡点、下一步和关联资料，并保存到原任务对象。安全链接只允许 HTTP(S)，旧备份里不安全的 URL 不生成可点击链接，原始备份内容不被删改。
- **齐行项目页**：任务行显示下一步/上次进度与保存信息；工作台沿用项目任务和事件服务。已从 `ProjectsView.vue` 抽出工作台状态、事件标签、任务摘要和组件，降低页面复杂度。保存遇到过期版本会报告冲突，不静默覆盖。
- **日程/课程/项目数据**：没有复制课程、日程或任务数据；继续复用 `courseId` 和现有个人/协作实体边界。
- **备份恢复**：新任务断点随任务对象一起进入现有备份与账号快照结构；新增往返用例。恢复仍按备份内实际字段和选择的模块执行，未选模块不会被清空。

## 4. 数据库与备份安全核对

- Supabase MCP 确认 `study-life` 远端已有 `team_project_tasks`、`team_project_task_events` 等齐行表，相关公开表启用 RLS；检查没有查询业务行内容。
- `supabase/migrations/20261009072859_qixing_task_workbench.sql` 只创建/授权两个 `SECURITY INVOKER` 函数，复用既有追加式事件表；正式库已登记迁移 `20261009072859`。没有删表、删行或重写项目任务，本地文件名已和远端迁移号对齐。
- 官方 Supabase 指南建议数据库函数优先使用 `SECURITY INVOKER`，并为需要调用的角色明确限制 `EXECUTE` 权限；本迁移采用该模式，只授予服务角色调用。见 [Database Functions](https://supabase.com/docs/guides/database/functions) 与 [Row Level Security](https://supabase.com/docs/guides/database/postgres/row-level-security)。
- 备份恢复检查确认：选择性恢复先保存本机检查点；执行失败能回滚；任务对象字段可往返保留。此核验覆盖代码和自动化用例，不代表已对用户正式备份文件做恢复演练，也不代表 Supabase 云备份已恢复验证。
