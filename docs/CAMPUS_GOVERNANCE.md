# 校园与管理中心闭环

## 入口和权限

管理中心的「校园内容与审核」入口通往 `/admin/campus`。数据库 `platform_admins` 中的 `owner` 是总管理员；前端不硬编码管理员邮箱。审核员使用独立的 `campus_reviewer_grants` 授权，不能管理账号、授权他人或变更总管理员身份。

总管理员进入「审核人员」，用完整邮箱查找已注册并完成邮箱验证的账号，填写学校、校区及操作原因后授权。学校名称须与校园资料一致；校区留空表示该校所有校区，指定校区仅能审核该校区的内容。修改和撤销授权都保留操作记录，后续请求重新检查权限。被暂停的账号不能审核，但其授权仍可撤销。

## 投稿、举报和反馈

1. 发布前可以预览公开字段。各类内容分别保存草稿，成功发布或清空当前表单只清除该类草稿。
2. 投稿进入统一待处理队列，覆盖地点、指南、活动、二手、课程评价、拼车、互助任务及争议。审核员仅能读取授权范围，不可审核自己的内容或参与的争议。
3. 投稿者在「我的投稿」查看状态、处理说明，撤回内容或修改后重新提交。撤回保留历史记录。
4. 用户对公开内容提交举报；同一用户不能对同一内容重复提交待处理举报，也不能举报自己的内容。补充说明仅用于举报处理，不作为公开正文展示。
5. 审核员查看举报及原文，填写依据后选择下架原内容、核实后结束处理或认定举报不成立。下架需要再次确认；正在履约的互助任务通过争议流程处理。
6. 举报结果、内容下架、审计记录和双方通知在一个数据库事务中保存。向作者发送的反馈不含举报人身份。用户在「我的举报」查看结果，通知提供对应模块入口。
7. 举报人对“未成立”的结果可在结果后 7 天内申请一次复核，补充说明为 10–500 字。复核单进入原授权范围的待办队列，由不同于原处理人的审核员处理；复核可维持原结论、确认问题或下架内容。原处理、申诉材料和复核结果分别留档。
8. 举报和复核均显示提交后 72 小时的处理目标时间。它是运营目标，不自动关闭记录，也不构成逾期自动通过或拒绝。

## 一致性和隐私

数据库对队列读取、审核、授权、举报处理和撤回重新检查身份与范围。内容版本或授权版本变化时拒绝旧请求，避免覆盖他人的处理。敏感表开启 RLS 且没有客户端直读策略；新 RPC 仅允许服务角色调用。Edge Function 使用登录账号身份传参，不接受客户端伪造审核人。

切换账号时立即清除列表、处理说明和表单状态，旧请求不得回填。审核失败保留当前队列和填写依据以便重试。

## 验证

`supabase/tests/campus_governance.sql` 使用虚构账号及内容，在事务中验证授权范围、自审阻止、版本冲突、举报事务与通知、撤权以及客户端访问隔离，结束时全部回滚。运行者需有创建测试账号及切换数据库角色的权限。

前端及 Edge 单元测试覆盖权限入口、授权参数、举报确认、失败保留、账号切换和现有发布流程。浏览器交互验证应使用隔离会话中的虚构数据，不向真实用户发送测试通知。
