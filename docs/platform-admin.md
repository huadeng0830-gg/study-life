# 平台运维

Study-Life 的业务记录以本机为主，账号同步和协作服务运行在 Supabase。平台运维页只管理认证账号及协作服务状态；它不能读取个人同步快照、课程、待办、账本或协作正文。

## 访问和登录

- 正式站点：`https://study-life.pages.dev/#/platform-admin`
- 从个人管理中心进入：登录平台所有者账号后，打开“管理中心”，选择“平台运维”。
- 使用 Supabase Auth 的邮箱和现有密码登录。没有单独的后台密码；忘记密码时走账号面板的邮件重设流程。
- 首位所有者为项目指定的已验证 Supabase 账号。后台角色保存在服务端 `platform_admins` 表中，不保存在浏览器、`user_metadata` 或用户可自行编辑的字段中。

## 已开放的能力

- 概览：逐页统计 Auth 账号数、进行中的协作项目数、协作资料数和最近一次真实查询时间。账号超过 50,000 时显示已扫描数量下限。
- 账号管理：按邮箱搜索，按页查看注册和登录时间、邮箱验证、账号封禁和禁发期限。账号限制按当前页批量读取，搜索防抖并丢弃过期响应。
- 账号封禁：验证身份后进入封禁告知页，暂停云端同步、校园互动、私信及项目协作；保留本人处理通知、本地功能和有备份确认的退出流程。后端每次请求检查当前数据库状态，旧访问令牌也受约束。平台所有者不能被限制。
- 禁止发布：与账号封禁独立设置，限制公开投稿、修改重提、评论、回复、发送私信、好友邀请及项目文字/成果提交。浏览、个人同步、收藏、撤回/删除自己的内容、拒绝邀请仍可使用；安全举报和既有互助争议保留。
- 时长与解除：支持 1 小时、1/7/30 天、自定义整数分钟/小时/天、指定本地时区解除时间及永久限制（需明确选择）。有效范围为 1 分钟至 100 年；到期按数据库时间判断，不需要定时任务，永久用空截止时间配合启用状态表达。管理员可调整时长或单独提前解除任一限制。
- 账号通知：设置、调整和提前解除均需填写 1–500 字原因。限制状态、审计记录和待阅读提示在同一事务保存；用户只能查询本人两种限制的最近一次说明、处理时间和解除时间，点击“我已知晓”仅标记已读。账号面板始终保留最近处理说明；活动页面前台每 2 分钟检查，恢复可见/在线时补读并去重，失败退避至最多 15 分钟，后台/离线停止请求。到期提示使用服务器时钟偏移，并在前台每 30 秒更新。
- 防覆盖：两种限制各有独立版本，管理员提交时携带看到的版本；过期页面返回冲突，要求刷新核对，不自动重放写入。
- 管理审计：服务端记录操作者、对象、操作、结果、原因和时间。

搜索最多扫描 50,000 个账号；达到上限且仍有下一页时，页面会提示结果可能不完整。账号列表只返回邮箱和认证状态，不返回用户 metadata、同步快照或业务内容。

## 服务端安全边界

- `platform-admin` Edge Function 保持 `verify_jwt = true`，并再次从 Supabase Auth 验证用户会话。
- 每次管理请求都在服务端查询 `platform_admins`；前端显示/隐藏入口不参与授权判断。
- 管理表启用 RLS，且只向 `service_role` 授权。`anon` 和 `authenticated` 没有读取或写入权限。
- `service_role` 仅存在于 Supabase Edge Function 运行环境，不进入网页包、Cloudflare 环境变量或 Git。
- 当前只开放一个平台所有者。后台没有账号删除、角色自助提升、数据库恢复、读取用户私有内容等能力。

## 数据库和发布

基础迁移：`supabase/migrations/20261013013521_platform_admin_console.sql`。账号限制扩展：`supabase/migrations/20261016140858_platform_account_restrictions.sql`。

迁移只新增两张服务端管理表及索引，不改写现有账号、快照或协作数据。部署顺序：先应用数据库迁移并绑定所有者，再部署 `platform-admin` Edge Function，最后发布网页版本。Cloudflare Pages Git 集成从 `main` 构建网页；Supabase 迁移与 Edge Function 需要单独部署。

如果需要回退网页代码，恢复到之前的 Pages 部署即可。新表是附加结构；代码回退时保留迁移和审计记录，不要自动删除或重置生产数据库。

SQL 回归检查保存在 `supabase/tests/platform_admin.sql`。本地 Supabase 测试环境运行后，它会确认 owner 唯一性、匿名/普通账号无法访问管理数据，并在事务回滚后清理虚构测试行。

账号限制角色回归见 `supabase/tests/account_restrictions.sql`：独立期限、永久/过期、版本冲突、owner 保护、本人通知与跨账号隔离、旧 JWT 同步/资料/Storage 路径、单独解除、原子审计均使用虚构数据并回滚。部署顺序必须为增量迁移 → campus-life / campus-community / campus-social（包含共享权限模块）→ platform-admin → 网页，避免管理端先启用限制而旧业务服务尚未检查权限。

限制表不向浏览器开放。自查和已读 RPC 使用 `auth.uid()`，不接受目标账号；管理 RPC 仅给服务端且再次核对 owner。账号列表只批量关联当前页，不增加逐账号查询或 Realtime 频道。业务函数多一次最小权限 RPC 往返用于实时授权，不缓存权限；个人同步/资料和项目文件的直连路径另有 restrictive RLS，保护已有归属策略。

兼容旧版 Auth 原生暂停：列表保留原 `banned_until`，通过新管理操作转换/解除时，先保存应用限制和通知，再使用受支持的 Auth Admin API 解除原生暂停。原生解除失败会明确提示仍受旧封禁影响，不显示完全恢复；不会直接改写 Auth 表。旧原生封禁的新登录只能显示通用封禁提示，详细原因需管理员核对后转换。

权限检查不承诺撤销已经下载的数据、尚未过期的 60 秒文件签名 URL，或撤销封禁前已通过检查的在途业务请求。前端通知用于说明状态，最终授权以每次服务端检查为准。
