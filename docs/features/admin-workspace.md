# 管理工作区

管理中心使用一套导航和单一内容区，移动端通过功能选择框切换。平台管理与当前设备的个人数据分开；功能入口由服务端授权决定，所有读写操作仍由原接口验证身份和权限。

| 分区 | 入口 | 用途 |
| --- | --- | --- |
| 管理概览 | `/admin` | 显示待回应反馈、处理中反馈、校园投稿与举报、地点审核的实时数量；失败显示不可用 |
| 反馈处理 | `/admin/feedback` | 默认按支持数优先处理未完结反馈，全量搜索、筛选、每页 40 条摘要，逐条展开详情 |
| 内容审核 | `/admin/campus` | 审核队列、举报、争议及完整处理记录 |
| 审核人员 | `/admin/campus?tab=reviewers` | 管理授权范围、审核员申请、随机复核 |
| 地点审核 | `/platform-admin?section=places` | 地点资料队列、审核与分页 |
| 账号管理 | `/platform-admin?section=accounts` | 账号搜索、分页、暂停与恢复 |
| 操作记录 | `/platform-admin?section=activity` | 合并账号、地点和校园最近操作，按类型筛选、每页 20 条；展开后查看原因与对象编号 |
| 运行维护 | `/platform-admin?section=system` | 暂停或恢复注册、检查服务、查看平台计数与网页版本 |
| 本机数据 | `/admin?section=data` | 备份恢复、个人数据体检与修复、本机运行状态、按需展开版本与诊断 |

所有管理入口都进入同一个工作区。总管理员看到完整功能；审核员只能看到授权的校园任务；普通账号保留本机数据与公开反馈入口。旧 `/campus/feedback` 地址继续保持删除，不增加第二套反馈入口。

各工具按需加载。进入地点审核不会查询账号列表，进入账号管理不会运行平台全量统计。管理导航在桌面随页面滚动保持可用。查询参数可用于收藏分区和反馈处理状态；切换账号立即卸载旧账号的管理内容，迟到请求不能恢复旧权限。

操作记录仅展示各接口最近返回的记录，不充当完整历史导出。地点接口已经包含校园审核中的地点事件，合并时按事件编号去重；地点接口失败时仍可保留校园历史返回的地点记录。

注册开关由服务端数据库在 `auth.users` 插入前执行，覆盖直接认证请求和所有新建用户的登录提供方；现有用户登录及密码找回不会插入新用户，因此保持可用。只有总管理员能修改开关，提交携带版本时间，状态与审计在同一事务保存。公开接口只暴露是否开放注册，操作人等元数据不向普通用户开放。恢复只开放当前已配置的注册渠道，不会替项目启用新的邮箱或第三方提供方。

上线先应用 `20261016055900_feedback_support_votes.sql`、`20261016060511_platform_registration_control.sql`，再部署 `campus-community`、`platform-admin`、公开 Worker 与 Web/PWA。注册初始保持开放，当前项目已有的提供方配置保持不变。数据库回归全部使用虚构数据并回滚。

`tests/adminWorkspace.test.js` 检查按需读取、权限隔离、账号切换、失败状态、过滤深链、日志去重与目标追踪。`feedbackSupport.test.js` 和 `registrationControl.test.js` 检查并发点赞、账号切换、确认及失败状态；数据库测试在真正的 Auth 角色下检查暂停和恢复。原本机数据、校园审核和反馈处理的行为测试继续覆盖修复、撤销、确认、分页及并发处理。本次仅发布 Web/PWA。
