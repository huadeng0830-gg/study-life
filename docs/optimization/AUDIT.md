## 1. 核心结论与根因

项目已经积累了有价值的工程保护：统一路由元数据、领域命令与选择器、本机持久化/镜像恢复、账号版本同步、协作上下文隔离、项目事务与 revision、虚拟列表和大量回归测试。这些应保留。

## 3. 必须首先解决的实际缺陷

### A01：下拉框有视觉变化，业务状态不变

本项原始复现保留如下；2026-10-11 已修，当前范围与回归结果见 STATUS 第 0 节，不再列为开放缺陷。

`changeSelect(key)` 返回 `(event) => { … }`。Vue 把当前模板编译为 `$event => changeSelect('sort')` 等，既没传 `$event`，也没调用返回函数。浏览器使用合法选项 `created`、`low`、`unplanned` 发出 change，地址和列表投影均不更新。含一条高优先级的已安排任务时，选低优先级后仍显示该任务；预期应筛掉它。这是功能失效，不是设计偏好。

后续修复只需要纠正事件合同，并补实际控件交互验收。不要通过换 Select 隐藏错误，也不要重写 taskViewQuery。保留其 URL 白名单、排序默认方向、智能筛选回退和异步导航世代保护。

### A02/A21：已修增量不能替代完整门禁证据

第一次默认并发全量测试：310 文件中 17 失败，2814 测试中 18 失败，包括超时/异步挂载时机与工程上限。随后在同一源码下完整执行 `npm test -- --maxWorkers=2`：309 文件通过、1 文件失败；2813 测试通过、1 测试失败，256.47 秒。剩余确定失败就是课表行数守卫，其他首轮失败未在限制并发复验中出现。

不要将首轮全部失败列为产品 Bug，也不要将复验包装成“全绿”。`npm run check` 会在测试步骤失败；本次没有为了变绿修改测试或发布元数据。

23:29 和 23:35 的增量 typecheck 都因新增 Spinner 的 TS2305 失败。不是依赖包确实没有图标：本机 `import('@lucide/vue')` 的 Loader2Icon/LoaderCircleIcon/LoaderCircle 都是 function；问题在手写 ambient 声明与实际包之间的类型合同。后续并行变更补齐声明，23:40 的 typecheck exit 0，A21 已通过该项复验。新增组件未进入页面也会被 vue-tsc 扫描，因此这类声明缺口仍需在稳定快照的门禁发现。

更新改造过程另有时间窗口：23:30 单文件增量回归 5 项失败（其中 2 项为 appUpdate 引用的 webUpdateController 尚未落盘，另 3 项涉及桌面状态时序/安装互斥/安装异常）；23:33 已变为 4 通过、1 失败；后续防护落盘后，23:35 同一测试文件 **5 项通过**。后者是最新的该文件验证，不能把过程中的失败永久列为未修缺陷，也不能代替更新改造后的全量测试/真实更新。完整日志保留在 STATUS 列出的临时证据目录。
