### 本机沙箱限制（不是代码问题，但会影响复现命令）

- 受限沙箱禁止 Node 使用管道 stdio 创建子进程，且不允许写 `dist/`、`node_modules/`、项目内 `.tmp`。因此：
  - `npm test` 必须走一次放宽权限的运行（日志见上）；在受限模式下用 `--pool=threads --configLoader native` 也能跑，但**单进程线程池会把 `process.env.TZ` 的运行时修改泄漏给并行文件**，产生 13 个文件的并行假红：`taskTimeLocalTimezone`、`anniversaryAnimation`、`festiveLunarAnniversaryHome`、`confirmDialogMigration`、`courseProgressView`、`globalSearchShortcut`、`learningWorkflow`、`ledgerDeleteVisibility`、`scheduleGridRoving`、`scheduleLazyDialogs`、`tabKeys`、`componentDeadCss`、`engineeringFrontendPagesCsp`。这 13 个文件在冻结树上单独复跑**全部通过**，官方 forks 池的整轮运行也全绿。
  - `npm run build` / `build:check` 需要写 `dist/`；受限模式下可改用 `--outDir` 指向工作区 `.tmp` 验证同等产物（本轮先用该方式验证，随后在放宽权限下跑通了官方 `build:check`）。
  - `npm run worker:check` 会 `spawn` wrangler（异步管道），受限模式下 EPERM，本轮未运行；本轮没有任何 `workers/`、`functions/` 改动。
  - `tests/componentDeadCss.test.js`（mkdir `tests/.tmp-dead-css` EPERM）与 `tests/engineeringFrontendPagesCsp.test.js`（mkdtemp EPERM）在受限模式下也会假红（真实断言通过）。
