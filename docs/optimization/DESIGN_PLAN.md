# 视觉与交互优化规划

初版日期：2026-10-10；更新：2026-10-11（Asia/Shanghai）。**全局设计基础已实施；本批已深度优化电脑端待办与周回顾，其余页面继续分批推进**。功能边界以 [INVENTORY.md](INVENTORY.md) 为准，问题优先级以 [AUDIT.md](AUDIT.md) 为准。当前设计系统合同与实际组件变更见 [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md)，新鲜验收见 [STATUS.md](STATUS.md)。

## 1. 产品结构与改造原则

保留“三两事”作为课程、待办、时间和生活记录的个人工作台，好友/项目作为有独立权限与状态的协作工作区。每个页面先回答“现在看什么、下一步做什么、更多信息在哪里”。新增 shadcn 组件只服务这些决策。

采取局部迭代：修正事件与入口 → 确定页面结构/状态矩阵 → 统一视觉合同 → 按模块组合已有原语 → 回归数据、移动端与权限。保留旧入口/地址兼容；任何功能删除都要先在台账中说明替代入口和数据处理。审计期间更新模块仍有并行改造，后续开始前先确认稳定快照并重跑完整门禁；A21 类型缺口已由并行改造补齐并复验，不依据本次初始构建覆盖增量状态。

## 3. 导航与设置

桌面保持分组侧栏和折叠；修正工具区单行三动作与内部横滚，常用工具整行或明确菜单。页面内学习导航在桌面避免与完整侧栏争夺同等视觉权重；在手机提供上下文切换，不能挤掉主要内容。

手机底栏保持 3 个可自选页面 + 快速记录 + 更多，默认今天/学习/日程。待办仍必须通过学习上下文与更多可达；齐行/账本等的路径不因收起卡片而消失。更多分组控制空白与滚动长度，常用功能优先；默认布局真源与同步默认同步更新。

设置按“外观与布局、日期与提醒、记录默认值、专注、账号与数据”理解组织。可先在现有弹窗中增加明确导航与相关表单入口，不必新增一整套设置路由。全局时区和默认提醒从“快速记录”中变得可发现，同时保留旧入口兼容。

## 4. 视觉合同

沿用 `theme.js` / `style.css` 的颜色语义和现有主题，桥接 `src/styles/shadcn.css`。先在现有主题和高对比度下核对，再考虑局部调整。此次不选新 preset、不重装全量组件、不切换 React、不批量覆盖原语。

| 规则 | 目标与实现边界 |
| --- | --- |
| 层级 | 页面标题、分区标题、正文、辅助说明 4 级；页面一级主要动作保持明确，普通功能不竞争实底主色 |
| 字号 | 中文正文以 14–16px 为规划起点，关键数字独立；高频辅助信息尽量 ≥12px。最终依实际密度/真机阅读验证，不机械替换所有字号 token |
| 间距 | 采用少数统一密度档（紧凑工具区、列表行、表单、内容分区），同级一致；页面避免“卡中卡中卡” |
| 卡片 | 用于独立内容组/不同背景或状态；同一个过滤器、零值指标、普通说明不单独升格为大卡。卡片需有内容或行动价值 |
| 按钮 | Button 原语决定 variant/size；业务只管布局。ActionButton 保留异步去重/取消/反馈，不替换成丢行为的静态 Button；统一文字动作 |
| 图标 | 导航/操作采用已安装 Lucide Vue 的一致笔画；Emoji 作为内容/氛围可保留。所有纯图标动作有名称；手绘 SVG 明确 fill/stroke |
| 颜色 | primary/foreground/muted/border/destructive 等语义映射继续复用；状态不只靠红/绿区分。原始颜色用于主题源/用户数据，不作为业务控件随处覆写 |
| CSS | 梳理全局 `.btn/.card`、scoped CSS、Tailwind important 的覆盖关系；逐组件验证后归并，避免同时调整所有层导致回归 |

建立少量代表性状态样例（按钮/字段/筛选/数据行/浮层），作为评审依据。先证明一致的高度、焦点、错误、禁用和加载行为，再推广到业务页面；不用铺满所有 UI 导出的组件展示页来替代产品验收。

## 5. 交互与移动端合同

| 场景 | 规则 | 验收重点 |
| --- | --- | --- |
| 简单创建 | 最少必需字段先出现；高级时间阶段/重复/资源折叠，保留清晰展开入口 | 标题、日期、保存能直接完成；展开后错误能定位 |
| 筛选/排序 | 改控件必须改变数据；当前条件可读、可一键清除；按页面既有 URL 合同恢复 | 真实 change/click，不只测 parser；结果数、实体和 URL 一致 |
| 行操作 | 一个主要下一动作，辅助菜单/动作表；完成与编辑不使用相同隐喻 | 列表/看板/月历/课程/项目动作矩阵，权限拒绝与已删除实体 |
| 异步提交 | 保留输入、防重复、明确成功/失败、提供重试；取消只取消本次请求归属 | 旧请求不清新输入，账号/项目切换不串结果；不要用单个 busy 锁死无关任务 |
| 草稿/关闭 | 复杂已有内容可恢复；明确取消与意外关闭区分；空表单不增加无意义确认 | Escape、遮罩、手势、返回、跨路由、切账号、恢复点 |
| 浮层 | 沿用 overlayStack 的栈/返回/焦点/滚动锁；统一 mobile Sheet 与桌面 Modal 布局 | 上层 Escape 只关上层；Tab 不漏到背景；关闭回触发位置；新 Reka Portal 不绕过历史栈 |
| 手机 | 首屏呈现业务内容；高级控件集中；触控主要目标规划 44px；安全区和键盘下操作可达 | 320/390/430、横屏、长标题、输入法、页面/浮层滚动；内部 overflow 与文档 overflow 分开测 |
| 状态反馈 | 加载、首次空态、筛选无结果、离线、权限、服务未部署、保存失败分别处理 | 有明确下一步和保留数据说明；不能把未知空闲/缺汇率/保存失败显示为成功 |
| 通知/提醒 | 普通备份提示紧凑；未保存/持久化失败突出；通知只宣称实际平台能力 | 当前提醒依赖 App 打开与系统授权，不能通过文案承诺后台必达 |
| 更新与恢复 | 展示真实检查/下载/应用/运行版本验证；已知字节才给百分比，否则不确定进度；错误有对应重试 | 保留并行改造加入的时序/版本/互斥保护；初始 IPC 快照不覆盖新事件，安装异常不伪装成功；5 项增量回归不代替完整升级链 |

Calendar、Popover、Tabs、Field 等使用现有 Vue 原语和当前 Reka API；下一阶段实施具体组件前按 shadcn 技能获取对应文档。自定义 Modal/时间轮/滑动操作有额外领域与平台合同，不能机械删掉。

## 6. 代码边界与迭代路径

1. 局部修复 A01/A05/A07/A08，补真实行为证据；设计和数据模型保持稳定。
2. 为首页/待办确定少数据、正常、高密度三种结构，覆盖入口台账后再修改模板；课表抽出日期工具区/设置内容或编辑协调等真实职责，恢复 A02 门禁。
3. 统一共享控件与状态反馈合同，按一页一页推广；不同时改路由、存储协议和全部主题。
4. 复杂工作区沿已有 composable 边界拆分。页面只协调工作区、导航、选中实体与浮层；composable 管草稿/请求世代/命令；selector 负责纯投影；service 定义传输与错误；数据库保持授权与事务完整性。
5. 给关键实体、表单与 API DTO 补类型；收敛导航/配置真源；最后处理 A17 孤立代码。兼容迁移与用户数据始终保留。

- 存储/同步/协作改动必须额外检查保存后刷新、导出恢复、账号切换、双设备冲突、成员/角色拒绝、revision 和桥接幂等；视觉改动不能跳过受影响的数据行为。
- 云端/桌面部署与真机验证单独记录实际环境和结果；不把模拟浏览器或本地 SQL 证据写成生产通过。

## 8. 设计系统基础阶段（2026-10-11）

兼容性结论：沿用 Vue 3 + Vite + Tailwind v4 + shadcn-vue / Reka；不运行 React 初始化、不换 preset、不全量重装。theme.js / style.css 继续作为主题与基础 Token 真源，shadcn.css 负责桥接与组件配方。保留自定义 Modal / Sheet 栈、ActionButton、Toast 和 Sidebar 的有效实现。

本轮实施颜色角色、固定 4px 间距、14/16px 共享字号、行高、40/32/44px 控件密度、8/12px 控件/内容圆角、边框、克制阴影、图标、减少动态和手机规则；先对 Button、Input、Card 建立可复用视觉合同，再将 PromptDialog 接入 Field 表单与主次 Button。Modal / ActionButton 仅作 Token 接线，不改其状态和平台协议。具体值、状态矩阵、组件保留/整合决定、14 个源码文件和测试的实际增量逐项列在 [DESIGN_SYSTEM.md](DESIGN_SYSTEM.md)。

视觉检查使用隔离浏览器与虚构样例，同时观察首页、重要日期和账本三个实际消费者页面。没有重做全部页面，没有将 Tabs / Dropdown / Sidebar 或所有表单统一标成已完成；A06 只完成基础批，A11 只覆盖典型 PromptDialog 与基础浮层样式。后续先逐页解决层级与业务 CSS，再推广菜单/导航/复杂表单。本阶段完成后停止，等待下一阶段。
