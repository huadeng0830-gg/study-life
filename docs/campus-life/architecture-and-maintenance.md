# 校园功能的结构与维护约定

更新：2026-10-15。本文件描述当前源码及本地验证范围；不代表云端函数已部署。

## 用户流程

- 集市采用紧凑摘要列表，每页 20 条。搜索、发布方式、物品分类、价格/最新排序都由服务端在分页前处理。说明、收藏和举报按需展开；联系意向、私信及成交继续使用现有授权流程。
- 公开建议每页 20 条，审核申请区独立排版。公开列表、本人建议、审核申请和私信使用独立请求守卫，避免并发读取互相作废。
- 可约时间不再要求“课表确认完整至”和“学期结束日期”。成功同步后，实际课程、日程、考试与已确认邀约/会议以外的时间视为可邀请。课程仍按开始学期、起止周、单双周、调休与补课规则计算。
- 默认周一至周日每天 09:00–22:00 可邀请。星期、时段、最短时长与课程缓冲放在选填偏好中。星期采用周一为 0、周日为 6；缺少星期设置表示全部七天，明确空数组表示暂停邀请。旧的 `includeWeekends=false` 映射为工作日，用户可在新界面重新选择。
- 可邀请时间只是发出邀请的条件。新邀请保持 `pending`；接收方本人接受/拒绝，也可以提出改约。只有接受后才进入双方日程，确认时服务端重新检查版本、权限和冲突。客户端按双方最短时长的较大值选择时段。
- 未同步或损坏的快照仍显示无法读取，不能把数据缺失误当作空课表。只共享空闲时段，不向好友展示个人课程、账单或私密记录。

## 模块职责

| 模块 | 负责的规则 |
| --- | --- |
| `src/composables/campusPublication.js` | 发布类型、默认草稿、白名单字段转换、金额/日期/链接/班次校验；新发布和拒绝重提共用 |
| `src/services/campusPublication.js` | 发布请求分派、重提版本校验；请求正常完成即成功，不依赖响应正文是否为真 |
| `src/composables/availabilityPreferences.js` | 前后端共用的可约偏好归一化与星期约定 |
| `src/composables/campusLifePage.js` | 读取、写入反馈、卸载和账号切换隔离；读取与操作失败分开，较早操作不能覆盖最新反馈 |
| `src/composables/campusRequest.js` | 最新请求守卫、按条目去重的忙碌标识；旧账号请求完成不能解锁新账号操作 |
| `src/composables/campusLifeDraft.js` | 按账号保存兼容旧格式的本机草稿，保存失败显式提示 |
| `src/composables/campusFavorites.js` | 共享收藏读取、相同目标并发合并、账号隔离 |
| `src/composables/campusConfirm.js` | 确认框；切换账号或卸载后清除捕获的旧操作 |
| `supabase/functions/campus-life/rules.js` | 搜索内容类型、公开字段投影与字面量查询构造 |

服务端继续负责学校/校区范围、所有者、审核状态、版本及权限。客户端校验用于及时反馈，不能作为服务端授权依据。

## 查询约定

- `market_list` 接受 `page/query/listingType/category/sort`，返回 `listings/page/pageSize/total/hasMore`。页码从 0 开始，每页 20 条，最多允许第 2000 页。排序增加唯一 ID 作为稳定次序；价格为空时排在后面。
- `mine_list` 可传 `domains` 白名单，仅读取当前页面需要的投稿类型。省略时保留原来的完整响应。集市、互助、失物与课程页分别只加载对应类型，减少无关表查询。
- `search` 在数据库按关键词、学校/校区与公开状态筛选，再分页。综合搜索每个分类每页 6 条，最多 54 条；选择单一分类后每页 30 条。`hasMore` 表示至少一个分类还有下一页，不伪装成全库总数。
- 搜索不调用课程评分、校车站点、报名或私密申请查询。已取消活动、过期指南、归档或私有地点不会进入结果。
- 关键词按字面量匹配，不能把 `%`、`_`、`*`、引号或反斜杠变成过滤条件。实现使用 PostgREST `imatch` 以及 PostgreSQL `***=` 字面量前缀，再转义 PostgREST 引号值。[PostgreSQL 规则](https://www.postgresql.org/docs/current/functions-matching.html#POSIX-METASYNTAX)、[Supabase 组合过滤说明](https://supabase.com/docs/reference/javascript/or)。

## 兼容与上线

本次无需数据库迁移。原来的两个可空日期列保留，供旧客户端读取；新计算不再依赖它们。星期设置存于现有 JSON 偏好字段，原有投稿、私信、审核事件和本机草稿格式保持兼容。

发布时先更新 `campus-life`、`campus-social`、`campus-community` 函数，再发布 Web/PWA；旧前端可继续使用新函数的默认参数。新前端依赖新的分页与免日期保存能力，因此不能只发布前端。回退前端时保留数据及偏好；旧前端可能重新提示日期，需同时安排兼容策略。本轮未发布 Windows 安装包。

## 验证与扩展

回归覆盖旧内容搜索、跨学校/校区隔离、特殊字符、分页不重叠、按类型读取投稿、草稿存储失败、重复操作与账号切换、可约星期、无覆盖日期、实际日历占用和双方最短时长。浏览器用完全虚构的 100 条商品验证 390px 手机与 1280px 桌面分页、详情展开及横向溢出；审核申请表单的下边缘必须位于下一区块上方。

后续扩展应继续遵守这些约定：

1. 新内容类型同时添加发布转换、搜索投影、状态文案和服务端授权测试，不在各视图复制独立规则。
2. 内容增长后，以真实查询计划和延迟决定是否引入 trigram 索引或搜索 RPC；当前字面量查询解决截断前筛选问题，未宣称完成大规模数据库性能验收。分页采用 offset，持续插入或状态变化时仍可能改变相邻页，刷新可重新取得最新结果。
3. 学校归属仍是自填信息，不等于学校认证。校方身份、图片审核、支付和官方班次来源需要独立接入，不能用界面标识代替。
4. 线上跨账号/跨校验收应使用获准的测试账号；本地模拟查询不能代替真实 PostgREST 执行和生产验收。测试产物、截图和日志留在忽略目录，不能提交真实用户数据。
