# 校园生活中心实施与发布记录

日期：2026-10-14。校园生活中心已从地点目录扩展为真实服务端支持的多个校园业务模块。所有校园共享内容都从已登录账号的学校与校区资料确定范围，并经过服务端校验；待审内容不会进入公开列表。本文件同时列出尚未具备的身份核验、地图与图片等外部能力，不把它们描述成已交付功能。

## 权限与数据边界

Edge Function 验证 Supabase 会话和邮箱确认状态，并从服务端个人资料读取学校与校区，不接受请求体覆盖范围。公开查询按学校、校区和审核状态筛选。新增业务表启用 RLS，撤销 `anon` 与 `authenticated` 的直接表权限，只向 `service_role` 授予访问；数据库 RPC 也只授予服务端角色执行。私信仅允许发布者与对应的有效联系对象一对一读取和发送，拒绝不同申请人互相联系。

学校/校区目前是用户自填资料，邮箱确认不等于学校成员认证。它能提供一致的产品筛选和基础隔离，不能证明用户真实属于该校；若需要真实校内成员边界，必须先接入可信的校方身份来源。当前审核权限是登记的平台所有者，没有校级管理员分权。

地点个人记录仍保存在本机；校内分享内容单独存于 Supabase。新迁移只扩展地点目录和新增校园业务表，不迁移本机到访、消费、备份或私人备注。私密认领证据、私信正文和用户联系意向不出现在公开列表。

## 状态流转与审核

集市预留、互助接单、活动名额、失物认领、纠纷裁定、课程评价版本递增、拒绝后重提和通用内容审核均使用数据库事务/RPC。申请建立时锁定对应商品、任务或失物记录，避免状态刚关闭仍创建有效申请。审核内容版本与待审状态在同一事务中核对；状态更改和审计事件原子提交。审核队列按创建时间排序、逐页读取，并提供校车线路的关联站点/班次与课程安排的课程/教师名称。拒绝内容可由原作者修改并重新进入审核，数据库校验所有者、拒绝状态和版本号；改动不会覆盖原有审核事件。通知作为独立副作用失败时会记录服务端告警，不会把已提交的业务写入伪装成失败；活动重复请求按报名版本去重。

投稿者可在“我的投稿”查看自己不同学校上下文中的审核与业务状态、拒绝理由，并从拒绝记录进入预填表单修改后重提。课程评价也会回填本人已有评价，允许按原评价记录修改。修改提交前会检查内容版本，避免覆盖审核员或其他新版本的处理结果。
