## 个人学习生活工作台

底部入口与网页版的工作区对齐为「今天、学习、记录、校园、更多」，默认颜色取自网页版 DESIGN_TOKENS.md。

- 今天：当天课程和日程时间线、待处理待办、重要日期、本周收支、专注与心情。
- 学习：按日期查看课表，学期起始周、单双周、课程起止周，课程关联待办和专注进度。
- 记录：一句话识别日期、时间和金额，再进入可编辑的确认表单；也可直接新建待办、课程、日程、收支、固定账单、重要日期、清单或笔记。
- 更多：账本、预算、周期账单支付、清单勾选、笔记、专注计时和历史、月度回顾、主题与学期设置、JSON 备份恢复。
- 校园：地点和七类校园内容目录、投稿、举报、我的投稿修改/撤回、审核与建议管理。

个人记录无需登录即可本机使用。登录后进入独立的微信账号空间；本机修改先落盘，联网后通过 study-life 云函数同步。不同设备同一记录发生冲突时暂停上传，由用户在「更多 → 数据管理」导出备份后选择版本。账单支付和专注回写保持成组事务。

`sl_personal_records` 已使用同样的禁止客户端直读直写权限，并创建 database.schema.json 中的索引。新建其他云环境时仍需按后面的部署步骤初始化。未填写 EnvID 时可以使用本机工作台，云登录和校园服务仍需配置环境。

云函数 record-model.js 是客户端 utils/record-model.js 的部署副本，测试要求二者字节一致；修改规范后应同步两份文件。

当前是原生小程序主要工作流，**尚未达到网页版全部功能等价**：OCR/Excel 课表导入、通知多事项解析、重复待办、特殊调课/多套作息、农历与壁纸、复杂多币种换算/退款、齐行协作与一起约等尚未迁移，不能把这些记为已完成。详细对照见仓库 docs/miniprogram-parity.md。

## 3. 创建数据库集合和权限

在云开发控制台选择**文档型数据库**，创建以下 13 个空集合：

```text
sl_accounts
sl_profiles
sl_content
sl_feedback
sl_reports
sl_applications
sl_grants
sl_wallets
sl_ledger
sl_limits
sl_moderation
sl_audits
sl_personal_records
```

每个集合进入「权限管理 → 自定义安全规则」，保存 `cloudfunctions/database.rules.json` 的内容：

```json
{ "read": false, "write": false }
```

所有业务读写由云函数完成。不要设置成“所有用户可读写”，否则客户端可以绕过学校范围、审核和奖励校验。

`cloudfunctions/database.schema.json` 是集合和复合索引的部署清单，**不会自动应用**。在每个集合的索引页按 `indexes` 创建索引：字段按清单顺序排列，`1` 为升序、`-1` 为降序，均为非唯一索引。`_id` 本身已有唯一性，无需再创建唯一索引。学校、校区过滤、审核队列和时间排序会使用这些复合索引；请等待索引完成构建后联调。

新环境没有校园内容，可通过小程序的「校园 → 任一分类 → 投稿」提交文字内容，再由另一账号的审核员或总管理员审核。当前七类目录提供文字信息展示、投稿、举报，不包含网页端的交易、接单或活动报名流程。

## 4. 上传云函数

1. 在开发者工具中选择上面创建的云环境。
2. 右键 `cloudfunctions/study-life`，选择「上传并部署：云端安装依赖」。首次创建时建议选择当前支持的 Node.js 20 运行环境；现有环境以云端详情为准。
3. 确认函数名为 `study-life`，入口为 `index.main`；随代码上传 `config.json` 中的 `security.msgSecCheck` 云调用权限。
4. 云函数固定依赖 `wx-server-sdk@3.0.1`，附有 `package-lock.json`。本地复现依赖可在函数目录执行 `npm ci --ignore-scripts`。
5. 小程序「我的账号 → 微信一键登录」建立独立账号。云函数从微信云调用上下文读取身份，无需客户端传 OpenID、登录 code 或自建 token。

资料、投稿、建议、举报说明、处理依据等文本使用微信内容安全检查。接口未授权、检查失败或结果不是 `pass` 时不会公开或提交对应内容；没有绕过检测的开发开关。请先确认小程序账号具备接口权限，且用真实微信账号测试。

不需要配置原来的 Supabase request 合法域名。当前版本没有附件上传，因此未开放云存储的客户端访问。

## 5. 设置总管理员

1. 使用管理者自己的微信登录小程序。
2. 在「我的账号」点击「复制账号编号」。这是对 `AppID:OpenID` 做 SHA-256 后截取的内部编号，不是原始 OpenID。
3. 在云开发控制台进入 `study-life` 云函数的环境变量设置，添加 `OWNER_USER_IDS`，值为该账号编号。多个管理员用英文逗号分隔，不要加引号。
4. 保存云函数配置，重新进入小程序「我的账号」，应出现「校园管理」。

不会把第一个注册用户自动设为管理员。不要把 `OWNER_USER_IDS` 配到客户端，也不要依赖本地缓存的 `owner` 标记授权；所有管理操作都在服务端检查。

「校园管理」可审批审核员、要求补充材料、撤销审核授权、处理建议和奖励、复核抽样记录。申请人须微信登录并填写学校资料，由总管理员核查后设置学校/校区范围，不再依赖旧网页端的邮箱认证。

## 6. 审核和账本规则

- 审核员只能处理授权学校/校区内的内容，不能自审，也不能处理自己参与的举报。校区级授权不能审核全校内容。
- 每次决定需依据与当前版本。内容状态、审核记录和奖励在同一事务中提交，重复提交或旧页面不会重复发奖。
- 每条审核奖励 3 个贡献豆，每个审核员按北京时间每日最多计入 20 条；同一目标只奖励一次，总管理员不领审核奖励。
- 约 10% 的非管理员审核稳定随机入样，自动进入复核队列。错判追回剩余贡献豆，不足转为待抵扣额，后续审核奖励优先抵扣；充值豆不受影响。
- 普通内容可在复核时重开，要求原记录仍是当时的版本；举报处理涉及原内容，不自动恢复被下架内容，需管理员核查后在云控制台修正。
- 建议通过内容安全检查后匿名公开。只有总管理员把建议设为「已解决」并填写奖励，才一次性发放 0–20 个贡献豆；奖励留空表示暂不发放。不能给自己的建议发奖励。
- 充值、兑换、用户间转账和提现未开放。
- 小程序“退出”清除本机业务登录标记；微信云调用身份由微信管理，不代表退出微信。

## 7. 联调验收

用两个测试微信账号验证以下流程（不要在公共仓库提交真实数据或截图）：

1. 普通用户登录、保存学校资料、提交建议；未登录可查看匿名公开进度。
2. 用户投稿后，目录里暂不可见；另一账号审核通过后同校可见，其他学校不可见。
3. 总管理员审批另一用户的审核申请；该用户收到审核奖励，重复点击不重复入账。
4. 总管理员处理建议并发奖励；重复保存不重复奖励。
5. 用户举报，审核员核对原内容和版本后下架；目录中不再展示。
6. 撤销审核权限后，旧审核页提交被拒绝，用户可以重新申请。
7. 在小程序端尝试直接读写数据库，应被安全规则拒绝。
